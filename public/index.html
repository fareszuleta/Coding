COLLABORATION

Build together.

Invite your team, assign roles, and share your workspace.

Up to 25 members

Invite by email

Add team members by sending an invite to their work email. They'll get access to the shared workspace and all project resources immediately.

CLI
nexo team invite user@company.com --role developer

Roles & permissions

Control access with three built-in roles: Admin (full control, billing, team management), Developer (read/write on projects, deploy access), and Viewer (read-only, dashboards).

CLI
nexo team roles --list

SSH keys & tokens

Each team member can register their SSH public key or generate a personal access token for CLI authentication and Git operations.

CLI
nexo auth add-key ~/.ssh/id_ed25519.pub
CONNECT

Integrations that work.

Connect your tools and automate your workflow.

6 integrations

GitHub

Connect your GitHub account to sync repositories, enable automatic pull request previews, and trigger CI/CD pipelines on every push.

CLI
nexo integrate github --org your-org --token ghp_xxxxxxxxxxxx

npm Registry

Publish packages to a private npm registry scoped to your workspace. Manage versions, access controls, and audit logs from one place.

CLI
nexo registry publish --scope @my-team --access restricted

API keys

Generate and rotate API keys for external services. Keys are scoped per environment (development, staging, production) and can be revoked at any time.

CLI
nexo keys generate --env production --name "CI Pipeline"

Webhooks

Set up webhooks to notify Slack, Discord, or any HTTP endpoint on deployment events, failed builds, and security alerts.

CLI
nexo webhooks add https://hooks.slack.com/services/T00/B00/xxx --events deploy,fail
SHIP IT

Deploy anywhere.

Push your project to production in one command.

3 providers

Cloud deploy

Deploy to Vercel, Render, or AWS with zero configuration. Nexo detects your framework, builds the project, and ships it.

CLI
nexo deploy --provider vercel --env production

Environment variables

Manage secrets and config per environment. Variables are encrypted at rest and injected at build time. Never commit .env files again.

CLI
nexo env set DATABASE_URL "postgres://user:pass@host/db" --env production

CI/CD pipelines

Auto-generate GitHub Actions workflows or GitLab CI configs. Run tests, lint, build, and deploy on every merge to main.

CLI
nexo ci init --provider github-actions --test --lint --deploy

QUICK GUIDE

A good place to start.

Nexo is a fictional platform with a working demo CLI. The included program prints information and examples in your terminal.

What do I need to use the demo?

Node.js 18 or later. Download the ZIP, extract its files, and open a terminal in the folder containing nexo.mjs.

What is a CLI?

It is a program you use by typing commands in a terminal. In this demo, node runs the file nexo.mjs and the last argument selects the action.

What is included in the download?

The source file nexo.mjs and a README.txt file. No extra packages, administrator permissions, or account are needed.

How does the Copy button work?

It copies the exact text of the visible block. If your browser does not allow copying, select the command and use your system copy shortcut. You can review it by pasting it into a text editor first.

My terminal cannot find “node.”

Check that Node.js is installed and available in your terminal. You can use the playground to explore sample output without installing anything.

How do I remove the demo?

Delete the extracted folder. The CLI does not change your system settings. You can reset the guide progress in Preferences.
